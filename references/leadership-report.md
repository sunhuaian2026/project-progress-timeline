# 管理层汇报：先交付判断，再提供证据

在用户明确面向老板/领导、管理层、项目周报或决策汇报时使用。报告服务于阅读者判断“进展怎样、目标能否实现、有什么风险、需要我做什么”，结论、结果、里程碑/偏差、风险/决策、下一步这五部分置于原首页顶部，随后完整追加原进度内容；技术过程仍保留在开发时间轴。内部汇报不自动获得公网发布或发送消息的授权。

## 从原始资料形成结论

核对当前批准目标、范围/验收口径、截至时间及上次已核验汇报。汇报期、计划日期、责任人、业务指标有来源则引用；缺失项留作未知。只有缺口影响核心判断时才合并提出必要问题，不让用户补一套无关表单。

区分三种判断，避免把一个“完成率”当成全部结论：

| 判断 | 可用依据 | 无依据时 |
|---|---|---|
| 交付就绪 | 当前目标的适用验收、真实可用结果及仍开放门槛 | 记录“尚不能判断”，任务关闭不替代交付验收 |
| 计划偏差 | 已批准的基线/日期与同口径实际或经确认预测 | 记录“未提供计划基线，无法判断是否按期” |
| 价值实现 | 可比的使用、成本、收入或其他业务原始指标 | 区分已交付能力、预期价值与已证实收益 |

“受阻”需要当前目标仍依赖该条件；历史失败不等于当前风险。“有风险”不自动等于已延期，没有日期依据不估算延期天数。观点或建议注明其证据及不确定性。

## 汇报顺序

1. **一句话结论。** 先说当前目标达到什么程度，再说最重要的限制/影响和需要采取的动作。显示截至时间；不以任务编号、测试数、模型或活动量开头。
2. **已交付结果与范围。** 选择对当前目标有影响的结果，写“谁现在能完成什么”，链接验收证据。技术实现、自测完成、真实验收和已上线分别表述。展示本期变化须有上期同口径基线；否则称“截至当前的状态快照”。
3. **目标/里程碑与偏差。** 给出已批准目标、当前结果和剩余门槛。有明确计划时才能对照计划日期/实际日期；没有时展示已验/未验及待对齐范围。图表优先表现交付状态与门槛，不能用首末开发记录冒充项目排期。
4. **关键风险与所需决策。** 每项写清问题、对当前目标的影响、现有处理、责任人和下一检查点；未知字段明示未登记。把“供知悉”“需要协调”“需要决策”分开。决策项提供具体选项、建议及取舍；只有真实需要上级决策才提出，不为凑内容制造审批。
5. **下一步。** 按“预期可观察结果 → 责任人 → 已确认时间或触发条件 → 验收方式”组织。没确认的日期不承诺；“下个里程碑”不暗示已获实施授权。

主结论保持一行或短段；风险随重要性取舍，严重问题不因版面限制被省略。首屏能够回答核心问题，解释和证据可展开。压缩文字时保留目标、适用条件、未验证项和责任边界。

## 页面与图表

- 原首页顶部先展示结论、结果、里程碑/偏差、关键风险/决策、下一步五部分，原有阶段、完成情况、图表与侧栏保持；不另设汇报页面或“管理层摘要”标签。重要阻断与未验边界直接可见，不折进“查看依据”。
- 首屏指标只选能帮助当前决策的交付或业务指标，并标明范围、基线和时间。任务数、测试数及事件柱图通常移到执行明细；没有业务数据时，用交付能力和验收门槛替代，不编造收益。
- 开发时间轴继续在顶部保留甘特记录图，下方按天折叠；管理层无需阅读这些过程图才能理解结论。源证据与完整记录继续保留。
- 计划/实际图、趋势或红黄绿状态必须有相应计划、连续样本或明确判据。没有依据时展示未知或具体状态，不自动涂绿。颜色配文字解释，不靠颜色单独传达判断。
- 汇报稿避免源码路径、SHA、模型名等实现细节挤占正文；证据入口可用“验收记录”“范围依据”等可理解标签，展开后保留原始信息。

渲染器通过 overview.json 的可选 report 字段支持此汇报布局，字段见 references/schema.md。它校验结构与证据引用，不自动抽取管理结论，也不保证语义判断正确；仍需核对原始事实。

## 合成示例：同一事实，两种表达

以下完全虚构：基础存储和查询切片已验收，集成尚未关闭，双设备验证缺资源，发布仍开放；无批准交付日期，无业务收益数据。

研发式摘要：

> 基础任务3/3，整合与质量0/3，接口清单2/3；并发验证有一条blocked记录。

管理层式摘要：

> 基础存储与查询能力已交付，但整体集成和发布条件尚未满足。双设备验证是当前阻断，需先协调测试资源；尚无批准交付日期，暂不能判断是否按期。

结果：基础能力已有验收，完整产品仍未就绪。所需协调：落实双设备验证资源；责任人及就绪时间未登记。下一检查点：资源就绪后验证跨设备恢复，再复核整体验收。业务收益尚未测量，不作效率或收入承诺。

不能把这个示例的目标、风险、决策或数字套进其他项目。

## 复核交付

对每项结论核对来源及版本，尤其是“本期新增”“按期”“可发布”和“收益已实现”。人工读首屏时，不展开技术记录也能找出结论、重要限制、需上级采取的动作及下一检查点。存在验收冲突或缺资料时显式保留，不以漂亮图表掩盖。
